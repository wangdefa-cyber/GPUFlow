# GPUFlow 用户使用说明

- 版本：v1.0
- 适用环境：Windows 10/11、Anaconda、本地单机
- 默认数据库：`artifacts/gpuflow.db`

## 1. 启动系统

最简单的方式是双击项目根目录中的：

```text
start_gpuflow.bat
```

启动器会自动：

1. 切换到项目目录。
2. 激活 `gpu_analysis` Conda 环境。
3. 检查 Streamlit、Pandas、SQLAlchemy 和 Plotly。
4. 启动 Streamlit 并打开浏览器。

也可以手动启动：

```powershell
conda activate gpu_analysis
cd C:\Users\Auraro\Desktop\信息系统与设计
streamlit run streamlit_app.py
```

浏览器默认访问：

```text
http://localhost:8501
```

首次启动会自动：

1. 创建 SQLite 数据库。
2. 创建基础表。
3. 写入 7 台示范虚拟 GPU 服务器。
4. 写入 6 条示范用户任务。
5. 写入四种调度预设。

示范配置属于系统配置数据，不是历史数据。

## 2. 数据中心

数据中心包含四个页签。

### 2.1 数据概况

展示七张真实 CSV 的行数、字段数、文件大小、缺失单元格、重复行和 SHA-256 校验结果。

用途：

- 确认数据是否完整。
- 向评审展示真实数据规模。
- 解释探索性分析和历史观测覆盖率。

### 2.2 质量检查

展示：

- 状态性缺失。
- sensor / machine_metric 覆盖范围。
- GPU 指标口径风险。
- 脱敏相对时间。
- workload 与 GPU 型号标签覆盖率。

### 2.3 真实样例

读取真实 CSV 前若干行进行预览，并支持按状态过滤。

注意：

- 这是有限行数预览，不是全量分页查询。
- 时间字段是脱敏相对秒数。

### 2.4 数据库导入

推荐操作：

1. 选择历史样本任务数量，例如 20、50 或 80。
2. 点击“导入真实历史工作负载样本”。

系统会：

- 读取真实 terminated instance。
- 过滤时长不大于 0 的实例。
- 关联 task 资源计划。
- 关联 job 用户标识。
- 转换 GPU/CPU 百分比为当量。
- 写入历史回放任务和数据集版本。

限制：

- 当前为文件前部有界样本，不是全量回放。
- 历史 task 没有优先级，统一使用中性值 5。
- 同一文件与样本量重复导入会复用已存在的数据集版本。

## 3. GPU 资源管理

可以：

- 新增服务器行。
- 编辑名称、GPU 型号、容量、CPU、内存和状态。
- 删除服务器行。
- 恢复示范配置。

保存前会校验：

- 名称不能为空且不能重复。
- GPU 型号必须在支持列表内。
- 容量必须为有限非负数。
- GPU 容量必须大于 0。
- 状态必须合法。

保存后写入 SQLite。已经完成的实验使用冻结快照，不受后续服务器修改影响。

## 4. 任务管理

### 4.1 用户任务

可以动态增删改：

- 任务名称
- GPU 需求
- CPU 需求
- 内存需求
- 优先级
- 预计运行时长
- GPU 型号要求
- 到达时间

任务来源固定为 `USER_CREATED`。

### 4.2 历史回放样本

展示真实 instance 与 task 资源计划映射出的只读任务。

字段说明：

- 到达时间为样本内相对时间。
- 运行时长来自真实实例时间差。
- 优先级统一为 5。
- 资源量来自真实 task plan。

历史回放任务不能直接编辑。

## 5. 调度控制台

四种预设：

| 预设 | 排序 | 放置 |
|---|---|---|
| FIFO | 到达顺序 | First Fit |
| SJF | 预计时长升序 | First Fit |
| Priority | 优先级降序 | First Fit |
| Best Fit | FIFO | 多资源 Best Fit |

可以配置：

- 等待 SLA
- 随机种子
- 是否允许跳过队头

保存后成为默认调度配置。每次实验仍会保存自己的调度快照。

## 6. 动态仿真

### 6.1 实时步进控制

点击“创建实时仿真”后可使用：

- 开始 / 继续：每秒自动推进一个事件时间批次。
- 暂停：停止自动推进。
- 单步推进：只处理下一个事件时间批次。
- 运行到结束并保存：一次完成剩余事件。
- 重置：丢弃未保存的实时状态。

完成后自动写入 SQLite。

### 6.2 快速批量运行

页面下方可以直接创建一次完整仿真，参数包括：

- 实验名称
- 工作负载
- 调度预设
- 随机种子
- 等待 SLA
- 队头规则

### 6.3 结果查看

支持：

- 历史实验选择
- GPU 分配 KPI
- 仿真时间滑杆
- GPU/CPU/内存利用率曲线
- 任务甘特图
- 逐任务结果
- 调度事件日志
- 受阻任务提示

## 7. 策略对比

推荐流程：

1. 选择工作负载和随机种子。
2. 点击运行四策略批量实验。
3. 系统生成 FIFO、SJF、Priority、Best Fit 四个实验。
4. 在“选择兼容实验”中保留需要比较的实验。
5. 查看指标表、指标柱状图、GPU 利用率曲线和周转时间箱线图。

直接比较要求：

- 任务快照一致。
- 服务器快照一致。
- 随机种子一致。
- 等待 SLA 一致。
- 队头规则一致。

不兼容实验会被阻止。

## 8. AI 决策

1. 选择一个已有实验。
2. 点击“生成规则建议”。
3. 查看建议摘要、严重度和理由。
4. 查看每条建议引用的指标或任务证据。
5. 查看建议配置补丁。

如果建议包含 `scheduler_preset_hint`，可以点击按钮采用该预设。系统只会修改默认调度配置并标记建议已采纳。

容量类建议不会自动扩容，必须到 GPU 资源管理页人工处理。

## 9. 设置与溯源

可以查看：

- Python 和依赖版本
- 数据来源分类
- SQLite 数据库路径
- 下载系统配置 JSON
- 恢复服务器和用户任务示范配置

恢复示范配置不会删除历史回放样本、已完成实验、事件或建议。

## 10. 数据语义

### 真实历史数据

来自阿里巴巴官方 GPU Trace，只读。

### 系统配置数据

用户创建的服务器、任务和调度参数，可编辑。

### 仿真生成数据

由 GPUFlow 调度引擎生成，包含：

- 分配
- 状态变化
- 任务完成时间
- 利用率采样
- 指标

### AI 建议

来自规则引擎，带证据引用，不是历史数据或调度结果本身。

## 11. 数据库与备份

默认路径：

```text
artifacts/gpuflow.db
```

备份时关闭 Streamlit，然后复制数据库文件。

指定其他路径：

```powershell
$env:GPUFLOW_DB_PATH = "D:\gpuflow-data\gpuflow.db"
streamlit run streamlit_app.py
```

## 12. 常见问题

### 页面没有历史任务

前往“数据中心 → 数据库导入”执行历史样本导入。

### 四个策略结果相同

如果集群容量充足、任务资源类型互不冲突，四种策略可能产生相同结果。这不是程序错误。可通过减少容量或增加同型号任务制造竞争。

### GPU 利用率很低

检查 Makespan、任务稀疏程度和集群总容量。历史稀疏回放常见低利用率。

### 导入时间较长

导入需要扫描真实 task 和 job 表，当前约需数秒到十几秒。

### 测试退出时出现临时目录清理提示

这是 Windows 环境下 Streamlit AppTest 的清理提示，不影响 0 退出码和测试通过结果。

## 13. 当前限制

- 历史导入为有界文件前部样本。
- 未实现 backfill、抢占和资源预留。
- GPU 型号严格匹配。
- 公平性首版按用户计算。
- AI 使用固定阈值规则，未接大模型。
