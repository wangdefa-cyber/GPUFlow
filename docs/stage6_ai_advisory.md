# 阶段 6：AI 辅助决策

- 日期：2026-11-22
- 状态：完成
- 规则版本：`advisor-rules-v1`

## 1. 设计目标

AI 辅助决策只读取已完成实验的真实指标、任务结果、资源采样和配置，不直接修改调度结果。

实现遵守：

- 无证据不生成建议。
- 建议只提供候选行动。
- 调度预设变更必须由用户点击确认。
- 容量类建议只展示配置补丁，必须到 GPU 资源管理页人工修改。
- 不接入外部大模型也能完成首版建议闭环。

## 2. 规则目录

| 规则 | 触发条件 | 建议 | 严重度 |
|---|---|---|---|
| HIGH_WAIT | 平均等待超过等待 SLA | 检查容量或排序策略 | 中/高 |
| BLOCKED_TASKS | 运行结束时存在受阻任务 | 按缺失 GPU 型号增加容量或检查严格型号匹配 | 高 |
| LOW_GPU_UTILIZATION | GPU 利用率低于 30% | 评估缩减或整合 GPU 容量 | 低 |
| PRIORITY_STARVATION | 优先级 ≥ 8 的任务等待超过 SLA | 评估 Priority 或预留容量 | 中 |
| LOW_FAIRNESS | Jain 公平性指数低于 0.8 | 评估用户公平性配额 | 中 |
| STRATEGY_RECOMMENDATION | 同条件比较中存在等待更低且完成率不下降的策略 | 优先验证该策略 | 中 |
| NO_ACTION | 未触发上述异常 | 保持当前配置并继续观察 | 信息 |

## 3. 证据结构

每条建议至少包含一个证据：

- `RUN_METRIC`：实验 ID、指标名、值、单位。
- `TASK_RESULT`：任务 ID、名称、状态、等待时间、GPU 需求和型号。

建议记录持久化字段：

- `run_id`
- `recommendation_type`
- `severity`
- `summary`
- `reasoning`
- `evidence_json`
- `suggested_patch_json`
- `rule_version`
- `accepted`

## 4. 用户确认边界

### 可自动采用的建议

只有存在 `scheduler_preset_hint` 时，用户可以点击“采用该调度预设”。

系统会：

1. 把对应调度配置设为默认。
2. 沿用原实验的随机种子、等待 SLA 和队头规则。
3. 将建议标记为已采纳。
4. 不修改任何已完成实验。

### 不可自动采用的建议

- 增加/减少服务器容量。
- 修改 GPU 型号比例。
- 用户公平性配额。
- 任何需要业务判断的资源配置。

这些建议只展示 JSON 补丁，由用户在 GPU 资源管理中人工编辑。

## 5. 页面能力

AI 决策页现在支持：

- 选择历史实验。
- 查看平均等待、GPU 利用率和受阻任务。
- 生成并持久化规则建议。
- 查看每条建议的严重度、理由和规则版本。
- 查看指标/任务证据表。
- 查看建议配置补丁。
- 采用调度预设建议。
- 标记无需自动执行的建议为已采纳。

## 7. 当前限制

- 规则阈值目前为固定配置，尚未提供可视化阈值编辑。
- 尚未接入外部大模型。
- 容量类补丁不自动应用到服务器配置。
- 建议优先级、SLA 和公平性目标仍需课程评审确认。
- 建议生成基于单个实验及其兼容批量实验，不做跨数据版本推断。
