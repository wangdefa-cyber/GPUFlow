# ADR-0001：采用模块化单体

- 状态：已接受
- 日期：2026-11-22

## 背景

GPUFlow 是单机部署的课程与实验系统，主要用户在一台电脑上导入数据、运行仿真和查看结果。当前没有独立扩容、独立发布或多团队并行开发的实际需求。

## 决策

采用一个 Streamlit 进程加一个模块化领域核心，共用一个 SQLite 数据库部署。模块之间通过应用接口和只读查询契约交互，不允许界面直接跨模块修改表。

## 取舍

- 避免微服务带来的部署、网络、分布式事务和运维成本。
- 保留清晰模块边界，后续如出现独立计算队列或大规模并发需求，可抽取仿真执行器。
- SQLite 作为共享物理基础设施，但历史、配置、仿真表的所有权必须明确。

## 重新评估条件

- 单个仿真运行无法在可接受时间内完成，且可通过独立工作进程解决。
- 多个用户需要并发运行实验。
- 数据规模导致 SQLite 查询或写入成为经证实的瓶颈。
