# GPUFlow v1.0 演示指南

## 1. 演示前准备

```powershell
conda activate gpu_analysis
cd C:\Users\Auraro\Desktop\信息系统与设计
streamlit run streamlit_app.py
```

建议提前完成一次历史样本导入，避免演示时等待文件扫描。

演示数据建议：

- 历史样本：20 条
- 调度预设：FIFO、SJF、Priority、Best Fit
- 随机种子：42 或 20261122
- 等待 SLA：900 秒

## 2. 10 分钟现场演示流程

### 第 1 分钟：项目定位

打开“系统总览”。

讲解：

- 数据来自阿里巴巴真实 GPU Trace。
- 七张表、约 1,594 万条记录、6,742 GPU 当量。
- 系统区分真实历史、系统配置和仿真生成数据。
- 项目不是静态图表，而是能运行调度实验的闭环系统。

展示点：

- 真实历史记录 KPI。
- GPU 容量图。
- 作业状态图。
- SQLite 运行状态。

### 第 2 分钟：数据真实性

打开“数据中心”。

讲解：

- 七张 CSV 的 SHA-256 与官方一致。
- 已检查行数、字段、缺失、重复和关联覆盖。
- sensor 只覆盖约 42%，machine_metric 只覆盖约 28%，不能冒充全量观测。
- 展示真实 CSV 有限预览和质量警告。

展示点：

- 数据概况表。
- 质量检查页签。
- 真实样例页签。
- 数据库导入页签。

### 第 3 分钟：真实历史导入

在“数据中心 → 数据库导入”中：

1. 选择 20 条。
2. 点击“导入真实历史工作负载样本”。
3. 说明导入过程关联 instance、task 和 job。

讲解：

- 资源来自真实 task plan。
- 时长来自真实实例时间差。
- 用户来自 job 表。
- 历史任务没有优先级，使用中性值 5，并记录该假设。

### 第 4 分钟：资源配置

打开“GPU 资源管理”。

展示：

- 7 台示范虚拟服务器。
- 不同 GPU 型号和容量。
- 动态编辑和保存能力。
- 数据写入 SQLite，而不是临时会话。

可操作：

- 修改某台服务器容量并保存。
- 再恢复示范配置。

### 第 5 分钟：任务与调度

打开“任务管理”和“调度控制台”。

展示：

- 用户任务与历史回放任务分离。
- 任务资源、优先级、到达时间和预计时长。
- 四种调度预设。
- 排序预览与静态容量预检。
- 排序规则与放置规则分离。

### 第 6 分钟：实时单步仿真

打开“动态仿真 → 实时步进控制”。

操作：

1. 创建一个 FIFO 实时仿真。
2. 点击“单步推进”两次。
3. 点击“开始 / 继续”。
4. 等待几秒。
5. 点击“暂停”。
6. 点击“运行到结束并保存”。

讲解：

- 状态由离散事件引擎推进。
- 不是前端随机动画。
- 完成后写入 SQLite。

### 第 7 分钟：仿真结果

在动态仿真页查看刚完成的实验：

- 平均等待、Makespan、GPU 利用率和完成率。
- 拖动仿真时间滑块。
- GPU/CPU/内存利用率曲线。
- 按服务器着色的任务甘特图。
- 调度事件日志。

讲解：

- 甘特图来自任务真实开始/结束时间。
- 资源曲线来自 `resource_sample`。
- 页面播放不会改变结果。

### 第 8 分钟：策略批量对比

打开“策略对比”。

操作：

1. 使用历史回放样本。
2. 点击运行四策略批量实验。
3. 查看默认选中的四个实验。

展示：

- 指标表。
- 指标柱状图。
- GPU 利用率曲线。
- 完成时间分布。
- 结果解读。
- 结果哈希和输入兼容性。

讲解：

- 四个实验共享同一冻结任务和服务器快照。
- 不兼容实验无法直接比较。
- 默认用户任务容量充足时四策略可能相同，系统不会伪造差异。

### 第 9 分钟：AI 辅助建议

打开“AI 决策”。

操作：

1. 选择刚完成的历史回放实验。
2. 点击“生成规则建议”。

展示：

- 建议摘要和严重度。
- 指标/任务证据表。
- 建议配置补丁。
- 如果存在策略建议，可点击采用对应预设。

讲解：

- 规则版本为 `advisor-rules-v1`。
- 无证据不建议。
- AI 不直接修改运行结果。
- 容量建议必须人工修改。

### 第 10 分钟：总结

打开“设置与溯源”。

展示：

- 环境版本。
- 数据来源分类。
- SQLite 路径。
- 系统配置下载。

总结：

- 已完成真实数据导入、资源配置、任务管理、调度仿真、动态展示、策略比较和 AI 建议。
- 当前限制已明确记录。
- 所有核心算法有自动化测试。
- 项目可本地运行、可复现、可追溯。

## 4. 演示备用方案

如果现场网络或数据扫描较慢：

1. 提前导入历史样本。
2. 提前运行四个策略实验。
3. 直接打开策略对比页并选择已保存实验。
4. 使用用户任务演示实时步进。
5. 数据中心仍可展示审计结果和样例，不需要重新导入。

## 5. 演示注意事项

- 不要称历史观测值为仿真利用率。
- 不要称 AI 建议为自动调度决策。
- 四策略相同不是失败，应解释输入和资源竞争条件。
- 展示百分比时同时说明容量和 Makespan。
- 历史时间字段是脱敏相对秒数，不是真实日历日期。
